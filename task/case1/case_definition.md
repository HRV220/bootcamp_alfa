# Паспорт кейса 1: время покупки Доминатора и винрейт

**Цель:** проверить, выше ли винрейт команды покупателя при ранней первой покупке Доминатора.

**Гипотеза:** среди покупателей Доминатора винрейт команды при первой покупке до 8 минут включительно выше, чем при покупке после 8 минут.

| Параметр | Определение |
|---|---|
| Предмет | Helm of the Dominator, `itemid = 164` |
| Единица анализа | Один покупатель в одном матче; учитываем только первую покупку |
| Ранняя группа | Первая покупка до 8:00 включительно |
| Поздняя группа | Первая покупка после 8:00 |
| Наблюдение внутри матча | От начала до завершения матча; исход — победа команды покупателя |
| Период данных | Вся доступная полная история RAW на фиксированный момент; точные даты установим при профилировании |
| Фильтр лобби | Исключаем матчи с `lobby_type IN (1, 4, 8)`; строки с NULL проверяем отдельно |
| Фильтр режима | Исключаем матчи с `game_mode IN (15, 18, 19, 20, 21, 23)`; строки с NULL проверяем отдельно |
| Метрика группы | Винрейт = число побед / число наблюдений в группе |
| Основная метрика | Разница винрейтов: ранняя группа минус поздняя, в процентных пунктах |
| Целевой порог | **Не менее +3 п.п.**, например 53% против 50% |

**Критерий успеха по целевой метрике:** разница винрейтов составляет не менее +3 п.п. Статистическую уверенность в результате оцениваем отдельно; метод определим до проверки гипотезы.

**Кейс выполнен**, когда подготовлены проверенные данные, воспроизводимо рассчитаны метрики и их неопределённость, сделан вывод о достижении порога. Отсутствие подтверждения гипотезы тоже является допустимым результатом.

При оценке неопределённости учтём зависимость покупателей внутри одного матча. Ранняя покупка может отражать уже имеющееся преимущество, а поздняя возможна только в достаточно длинном матче. Найденная связь сама по себе не доказывает причинного влияния покупки на победу.

## Что делаем дальше

1. Схемы четырёх RAW-таблиц из [модели данных](data_model.md) и примеры значений просмотрены. Следующий шаг — проверить качество на всём наборе; названия героев добавим, если справочник доступен.
2. Фиксируем дату среза, доступные версии таблиц и период по времени начала матчей. Проверяем полноту истории и пропущенные загрузки: в источниках данные очищаются каждые четыре часа, а глубина RAW ещё неизвестна.
3. Проверяем единицы времени, пропуски, дубли покупок, связи и исходы. У каждой покупки должен быть ровно один матч и один участник. Проблемные записи и потери строк объясняем.
4. Собираем первую покупку на пару «матч–покупатель». Показываем число наблюдений, матчей и аккаунтов, среднее и медиану времени, размеры ранней и поздней групп. Порог 8 минут задан заранее, а не рассчитан по данным.
5. До сравнения винрейтов определяем фильтры, статистический метод и достаточность данных для эффекта +3 п.п. Результат оформляем в ноутбуке с запросами, проверками и выводом.

**Первые наблюдения по примерам пользователя:** предмет `164` соответствует Доминатору; встречаются покупки по обе стороны порога 8 минут. В строках участников есть `rank = NULL`, а в матчах — разные режимы и типы лобби. Доля пропусков среди покупателей ещё неизвестна. По решению пользователя исключаем лобби 1, 4 и 8 и режимы 15, 18, 19, 20, 21 и 23; остальные фильтры ещё предстоит определить.

**Текущий статус:** структура и примеры значений изучены; полных проверок качества и результатов анализа пока нет. RAW только читаем, секреты подключения в документы и вывод не включаем.
