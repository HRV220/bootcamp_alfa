# Кейс 1. Доминатор: проверка цели и гипотезы

Дата анализа: 14.11.2026. Папка `night` исключена. Проверены постановка, SQL STAGE/MART, модели данных, скриншот дашборда и lineage. Кластер повторно не запускался; выводы относятся к сохранённым артефактам.

**Вывод: на сохранённом дашборде направление гипотезы подтверждается, целевая разница +3 п.п. достигнута: наблюдается +7,49 п.п. Полное выполнение исходного аналитического протокола и статистическая уверенность пока не подтверждены.**

## Что ожидалось

По [паспорту](case_definition.md) единица анализа — покупатель в матче, предмет — `itemid = 164`, учитывается первая покупка. После очистки рассчитывается единая медиана времени; ранняя группа — время не больше медианы, поздняя — больше. Проверяется, выше ли винрейт команды покупателя в ранней группе. Цель — разница не менее +3 процентных пунктов. Неопределённость должна оцениваться с учётом зависимости покупателей одного матча.

## Почему наблюдаемый результат поддерживает гипотезу

На [скриншоте дашборда](1.1.png), в таблице «Winrate dom early and late», сохранены:

| Показатель | Ранняя покупка | Поздняя покупка |
|---|---:|---:|
| `is_early` | true | false |
| Винрейт | 0,544 = 54,40% | 0,4691 = 46,91% |
| Число наблюдений, отображённое округлённо | 6,04 тыс. | 5,99 тыс. |
| `delta_vs_50_pp` | +4,40 п.п. | −3,09 п.п. |
| `median_buy_min` | 8,6 | 13,8 |

Расчёт по отображённым значениям:

`Δ = (0,544 − 0,4691) × 100 = +7,49 п.п.`

Следовательно, `Δ > 0`, что соответствует направлению гипотезы, и `7,49 ≥ 3`, что удовлетворяет целевой метрике. Превышение цели — **4,49 п.п.** Это описательное подтверждение на показанной выборке. Цифры округлены интерфейсом; точные количества побед и наблюдений не выгружены.

Столбец `delta_vs_50_pp` сравнивает каждую группу с 50%; основная проверка требует сравнения групп между собой. Значения 8,6 и 13,8 — показанные медианы внутри групп, их нельзя объявлять общим порогом разделения. Значение общего порога на скриншоте отсутствует.

## Что реализовано и чем это доказано

| Ожидание | Фактическое доказательство | Вывод |
|---|---|---|
| Подготовка матчей и участников | [matches_fixed.sql](stages/matches_fixed.sql), [match_players.sql](stages/match_players.sql): выбор версий, приведение состава, фильтры режимов/лобби в запросе матчей | Код есть; соответствие всех зависимостей требует сверки |
| Первая покупка каждого покупателя | [dom_buyers.sql](mart/dom_buyers.sql): `MIN(time)` по `(match_id, steam_account_id)` | Реализовано |
| Общая медиана и ранняя/поздняя группы | `approx_percentile(buy_time, 0.5)` на `is_direct`, далее `buy_time <= median_sec` | Реализовано с приближённой медианой |
| Командный разрез | [team_dominator_stats.sql](mart/team_dominator_stats.sql): по пять слотов на сторону, две стороны, наличие предмета, первая покупка, длительность | Реализован дополнительный анализ на другом отборе |
| Витрины зарегистрированы в lineage | [dom_buyers](lineage1.1.png), [team_dominator_stats](lineage2.1.png): источники → RAW → STAGE → MART | Есть визуальное свидетельство зарегистрированных зависимостей |

Наличие lineage не доказывает успешность каждого запуска, SLA или совпадение версии SQL с дашбордом. Дашборд, в свою очередь, подтверждает наличие рассчитанных результатов, поэтому старые формулировки README «ещё не запускалось» нельзя принимать как единственный актуальный статус.

## Где выполнение расходится с исходными ожиданиями

1. **Очистка до медианы выполнена не полностью по паспорту.** В `dom_buyers.sql` нет исключения покупателя с более чем двумя событиями Доминатора, исключения `account_id = 0`, проверки `buy_time <= duration`. Предшествующий `purchase_events.sql` этих ограничений тоже не содержит. Их выполнение во внешнем процессе не подтверждено сохранённым кодом.
2. **Неоднозначность аккаунта скрывается выбором строки.** Участник выбирается через `row_number()` по аккаунту с сортировкой по слоту. При нескольких слотах одного аккаунта это выбор первого, а не доказательство однозначной связи. Анонимный ID исключается из прямых соответствий; несопоставленные покупки остаются с `resolution = hidden` и не должны попадать в знаменатель винрейта.
3. **Расхождение медианы.** [README витрин](mart/README.md) описывает точную медиану и другие названия полей/таблиц, тогда как фактический SQL использует `approx_percentile`. Старые 10:15 из профилирования в паспорте также не являются доказанным текущим порогом.
4. **Разные имена зависимостей.** STAGE-запросы покупок и участников ссылаются на `stage.matches`, MART — на `stage.matches_fixed`, покупки MART — на `stage.purchase_events_new`. В файле матчей присутствует заголовок `matches_fixed:`. Нужен экспорт фактических определений процессов, чтобы установить, что именно исполнялось. `stages/items.sql` пуст.
5. **Период не проверяется текущей витриной.** В SQL не сохраняется `start_time`; принадлежность всех наблюдений 14–15 октября 2026 UTC по одним файлам подтвердить нельзя.
6. **Статистическая проверка не сохранена.** Нет выгрузки наблюдений, кластерного доверительного интервала или проверки чувствительности к составу групп. По округлённым агрегатам нельзя корректно учесть зависимости внутри матча.

Эти расхождения не отменяют показанные 54,40% и 46,91%, но ограничивают утверждение, что полученный эффект относится именно к полностью очищенной выборке из паспорта.

## Дополнительная гипотеза: наличие предмета у команды

Левая часть [дашборда](1.1.png) показывает заметное преимущество команд с Доминатором в матчах короче 30 минут; в более длинных матчах преимущество уменьшается или меняет знак. Точные значения и размеры подгрупп на графике не подписаны, поэтому численное доказательство для этого сравнения отсутствует.

Командная витрина исключает целый матч при наличии скрытого участника, а витрина покупателей использует прямые соответствия отдельных покупателей. Это разные выборки и разные единицы анализа. Командный график нельзя использовать как независимое доказательство эффекта ранней покупки. Общий вывод «Доминатор всегда повышает винрейт» графиком не поддерживается.

## Итог для отчёта и что нужно закрыть

**Формулировка результата:** «В сохранённом сравнении ранняя первая покупка Доминатора связана с винрейтом 54,40% против 46,91% при поздней покупке. Разница +7,49 п.п. превышает целевые +3 п.п. Результат поддерживает гипотезу на показанном срезе; причинный эффект и статистическая устойчивость отдельно не установлены».

Для полного закрытия: выгрузить фактический SQL и очищенные наблюдения с ключами и версией среза; согласовать фильтры и точную медиану с паспортом; пересчитать группы; оценить доверительный интервал кластерным bootstrap по `match_id` и устойчивость по героям, длительности и рангу. Сохранить общий порог, точные знаменатели и числа побед. Положительный результат исследования не требует утверждения причинности.

Арифметика повторяется скриптом [verify_evidence.py](../analysis/verify_evidence.py); исходные значения дашборда внесены вручную со скриншота. Скрипт не пересчитывает витрины и не оценивает значимость.
