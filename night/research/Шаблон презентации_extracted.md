## ppt/slides/slide6.xml
ETL
Cхема «SQL в UI → автоматический DAG в Airflow → RAW → STAGE → MART» + 2 скриншота (экран UI с SQL и граф DAG) + таблица потоков + блок «Как проверяем, что ETL работает». / Что заполнить: / легенда (1 строка): SQL пишется в UI, DAG создаётся автоматически, запуск по расписанию, команда работает с Airflow как пользователь — статус, логи, перезапуск; / процесс создания ETL: /  как из SQL в UI получается поток (шаги: написать SQL → проверить на тестовой выборке → описать таблицу / → /  сохранить → DAG сгенерирован → запуск по расписанию); / количество созданных потоков /  (например, «реализовано N DAG-ов: M загрузочных, K трансформационных»); / таблица потоков (3–5 строк): поток | что делает | вход → выход | правило «нового» | расписание; / Пример / с какими проблемами столкнулись /  (2–3 пункта: например, разные форматы дат в источниках, дубликаты в Mongo, нестабильное время ответа источника); / мониторинг и перезапуск: /  статус в Airflow UI → Grid (все DAG зелёные за N дней); при падении — Log → traceback → перезапуск через Clear / Rerun; сверка row count на входе/выходе. / Комментарий: /  не пересказывать SQL и не уходить во внутренности Airflow (trigger/sensor) — их строит платформа. Критерий закрывается тем, что видно: поток описан, инкремент определён, расписание есть, падение видно в логах, перезапуск возможен. Проблемы называть честно — это часть инженерной работы, а не минус. Частоту и глубину хранения не дублировать (они в паспорте витрин на слайде 4, здесь только ссылка). Чего нет (алерты, авто-тесты) — в «Рекомендации и развитие».
